API Reference

Abstract interface

Cached.AbstractCache — Type
AbstractCache

Supertype for all cache backends in Cached.jl.

A cache maps UInt64 hash keys to arbitrary values. Concrete subtypes persist results so that expensive function calls can be skipped on subsequent runs — even across Julia sessions when a persistent backend is used.

Interface

Subtypes must implement:

MethodDescription
cache[key::UInt64]Retrieve a stored value by key.
cache[key::UInt64] = valueStore a value under a key.
haskey(cache, key::UInt64)Return true if the key exists.
length(cache)Return the number of stored items.

Provided subtypes

  • DictCache — in-memory storage backed by a Dict.
  • FileCache — persistent storage on disk using Serialization.
  • SQLiteCache — persistent storage in a SQLite database.

Examples

using Cached

cache = DictCache()             # or FileCache("dir"), SQLiteCache("db.sqlite")
cmap(x -> x^2, cache, 1:5)     # compute and cache
cmap(x -> x^2, cache, 1:5)     # results retrieved from cache, f not called

Cache types

Cached.DictCache — Type
DictCache()

A cache that stores items in memory using a Dict. Items are not persisted and are lost when the Julia process ends.

Examples

using Cached

cache = DictCache()
cmap(x -> x^2, cache, 1:5)
source
Cached.FileCache — Type
FileCache(dir::AbstractString; clear = false, gitignore = true)

A cache that persists items to disk inside dir using Julia's Serialization module. Each item is stored as a separate file named by the hash of its key. Items are also cached in memory after first access to avoid redundant deserialization.

Arguments

  • dir: Path to the directory where cached files will be stored.
  • clear: Remove and recreate the directory if it exists (default: false).
  • gitignore: Create a .gitignore file in the cache directory ignoring all contents (default: true).

Examples

using Cached

cache = FileCache("my_cache")
cmap(x -> x^2, cache, 1:5)
source
Cached.SQLiteCache — Type
SQLiteCache(path::AbstractString; clear = false)

A cache backend that stores items persistently in a SQLite database at path.

SQLiteCache keeps an in-memory loaded dictionary for values accessed or written in the current session, while storing serialized values in a KeyValue table on disk so results can be reused across Julia sessions.

Arguments

  • path: Path to the SQLite database file.
  • clear: If true, delete any existing database file at path before creating the cache (default: false).

Notes

  • Keys are UInt64 hashes and values are stored as serialized blobs.
  • The constructor enables a SQLite busy timeout and initializes the table on first use.

Examples

using Cached

cache = SQLiteCache("results.sqlite")
results = cmap(x -> x^2, cache, 1:100)

Mapping functions

Cached.cmap — Function
cmap(f, cache::AbstractCache, c; showprogress = true, kwargs...) -> Vector
cmap(f, cache::AbstractCache, c1, c2, ...; kwargs...) -> Vector

Map f over collection c, storing and retrieving results from cache. Each input element is hashed with Base.hash to form the cache key, so any previously cached result for a given input value is reused without calling f again — even across separate Julia sessions when using a persistent backend.

The multi-collection form cmap(f, cache, c1, c2, ...) zips the collections and calls f(x1, x2, ...) for each tuple of elements.

Arguments

  • f: Function to apply to each element.
  • cache: An AbstractCache (e.g. DictCache, FileCache, SQLiteCache).
  • c: Collection of inputs.
  • showprogress: Display a progress bar (default: true).
  • kwargs...: Forwarded to ProgressMeter.progress_map.

Examples

using Cached

cache = SQLiteCache("results.sqlite")

# First call: computes and caches all values
results = cmap(x -> x^2, cache, 1:10)

# Second call: all results are retrieved from cache
results = cmap(x -> x^2, cache, 1:10)

# Multi-collection form
cmap((x, y) -> x + y, cache, 1:5, 6:10)

Cached.pcmap — Function
pcmap(f, p::AbstractWorkerPool, cache::AbstractCache, c; kwargs...) -> Vector
pcmap(f, cache::AbstractCache, c; kwargs...) -> Vector
pcmap(f, [p], cache::AbstractCache, c1, c2, ...; kwargs...) -> Vector

Parallel version of cmap. Maps f over collection c using the worker pool p, caching results in cache. Each input is hashed with Base.hash — cached values are returned immediately without dispatching to a worker.

When called without a worker pool, p defaults to CachingPool(workers()). If the pool contains no remote workers (or only the current process), f is executed locally without any remote dispatch.

The multi-collection form zips the collections and calls f(x1, x2, ...).

Arguments

  • f: Function to apply to each element.
  • p: Worker pool (optional; defaults to CachingPool(workers())).
  • cache: An AbstractCache (e.g. SQLiteCache).
  • c: Collection of inputs.
  • distributed: Whether to dispatch to remote workers (default: true). Set to false to run locally while still using the cache.
  • on_error: Called with (x, e) when f(x) throws. Forwarded to Distributed.pmap; nothing means errors propagate immediately.
  • retry_delays: Iterable of delays (seconds) for automatic retry on failure.
  • retry_check: Predicate (state, e) -> Bool controlling whether a retry should be attempted. Used together with retry_delays.
  • showprogress: Display a progress bar (default: true).

Examples

using Cached
using Distributed

addprocs(4)

cache = SQLiteCache("results.sqlite")

# Uncached items are computed on workers; cached items are returned immediately
results = pcmap(x -> x^2, cache, 1:100)

Utilities

Cached.wrap_cache — Function
wrap_cache(f, cache::AbstractCache) -> Function

Return a new single-argument function that wraps f with caching via cache. On the first call with a given input x, f(x) is computed and stored. Subsequent calls with the same x return the cached value without calling f.

The input is keyed by Base.hash(x).

Arguments

  • f: The function to wrap. Must accept a single argument.
  • cache: An AbstractCache used to store and retrieve results.

Examples

using Cached

cache = SQLiteCache("results.sqlite")
square = wrap_cache(x -> x^2, cache)

square(4)  # computed and cached
square(4)  # returned from cache

Cache maintenance

These functions are unexported (call them as Cached.loadall!, etc.) and apply to SQLiteCache.

Cached.close! — Function
Cached.close!(cache::SQLiteCache)

Close the underlying SQLite database connection. Call this when done with a SQLiteCache to release the file handle (e.g. before another process needs exclusive access); a closed cache should not be used again.
